# UI Atlas · 网页 UI 风格图鉴

60 个 UI 风格样例，覆盖**落地页 / 后台 / App** 三种形态。每一条都是**可复制的单文件 HTML**：打开就能看到完整页面，所有颜色、圆角、阴影、字体都写成 CSS 变量。

不是截图集，是个能动手的工具：改一个圆角滑杆，看 Bento 网格当场垮掉；把改过的链接发人，对方看到同一套改动；或者直接导出 Tailwind / shadcn 配置。

广度之外还有一层深度：[`ref.html`](ref.html) 把 Glass 一条**做穿**——75 个 token、十个页面覆盖三种产品形态（后台 / 公开页 / 移动端）、一张反例页和 7 条可判定规则。

## 跑起来

```bash
# Windows：双击 启动预览.bat
python serve.py          # 其他系统；默认 8760 起，自动挑空闲端口并打开浏览器
python serve.py 9000     # 指定起始端口
```

需要 Python 3.10+，无第三方依赖。**不要用 file:// 直接打开**：站点用 `fetch` 读 `styles.json`，浏览器会拦截。

## 一条风格，三种形态

40 多条落地页之外，还有 6 个代表风格各补了后台和 App 两种形态（共 12 个）：`glass` / `swiss` / `neubrutalism` / `ink` / `terminal` / `luxury`。

同一套 tokens、同一份风格 CSS，换一套骨架（`landing` / `admin` / `app`）。这样验证的不是「能不能画一个好看的首屏」，而是**这套设计语言能不能撑住表格和列表**——很多风格在后台形态下会立刻露馅。

## 为什么用生成器

所有样例共享骨架（导航 / Hero / 三卡 / 表单 / 页脚；后台是侧栏 + 统计 + 表格 + 分页；App 是 375 宽手机框 + 列表 + 标签栏），只有 CSS 与文案不同：

- 结构一致 → 对比时才看得出**风格差异**，而不是布局差异；
- 改一处（比如给所有样例加一个组件）只动生成器；
- 产物仍是**单文件 HTML**，独立可用、可直接复制。

```bash
python tools/gen_demos.py     # 生成 demos/ 与 styles.json
python tools/check.py         # 体检：0 错误才算过
```

## 加一个新风格

在 `tools/gen_demos.py` 里追加一个 `add(...)`：

```python
add(
    id="glassmorphism2", name="玻璃拟态 2", name_en="Glass 2", group="classic", era="2025–",
    tokens=dict(bg="#0b1020", surface="rgba(255,255,255,.10)", ink="#eef2ff",
                muted="#a9b4d0", accent="#7aa2ff", line="rgba(255,255,255,.22)",
                radius="20px", font="'Segoe UI',sans-serif"),
    features=["三到五条：这个风格能被一眼认出的决定性特征"],
    prompt="给 AI 的一段可执行提示词：颜色、圆角、阴影、禁止项都要写清。",
    brand="品牌名", h1="标题", lede="一句话说明",
    css="""
/* 只写与 BASE_CSS 不同的部分 */
""",
)
```

再在 `META` 里补 `sources`（流派与代表作品）和 `avoid`（什么时候不要用），最后跑一次生成器。`group` 取 `classic`（经典 UI）或 `shift`（从动效库平移）；想进形态矩阵就加进 `VARIANT_BASES`。

## 站上的五个功能

**改 token，实时看变化。** 详情页右侧的 tokens 是控件：颜色 → 取色器，`radius` → 0–40px 滑杆，字体栈 → 文本输入。改动通过 `iframe.contentDocument.documentElement.style.setProperty('--x', v)` 直接注入，所以是**真的在改那个样例**。每个颜色 token 右侧标着它对 `bg` 的 WCAG 对比度。

**分享改过的版本。** 改动会编码进 hash（`#/s/glass?r=0px&a=%23ff2d2d`），点「复制分享链接」把整条链接发出去，对方打开就是同一套改动，右侧高亮被改的 token。

**导出。** CSS 变量 / `tailwind.config` 的 `theme.extend`（colors + borderRadius + fontFamily）/ shadcn 的 CSS 变量（`--background`、`--primary`、`--radius` 等命名映射，hex 自动转 HSL 三元组）。

**对比。** 选两条，顶部一句结论（「圆角 22px ↔ 8px；底色一暗一亮」），下面逐 token 列出差异并高亮，两栏可同步滚动。

**搜索。** 同义词表 + token 特征词：`玻璃`/`glass`、`黑底`/`深色`、`圆角0`、`等宽` 都能命中；空结果时给三条最近的，而不是一句「没有」。

收藏与最近浏览存在 localStorage（不跨设备同步）。

## 版式：五套骨架，不是一套

最初的 60 条共用一套「nav + hero + 三张卡 + 表单」的骨架，48 张缩略图看起来就是同一个页面换了配色。问题在方法上：**风格的身份一半来自编排**——瑞士是超大字和网格，终端是等宽行和提示符，杂志是栏宽和衬线，海报是一整张纸。颜色只是最后一层。

所以生成器有一条 `layout` 轴（与 `form` 正交：`form` 是产品形态，`layout` 是页面编排）：

| layout | 骨架 | 数量 | 谁 |
|---|---|---|---|
| `landing` | 导航 + Hero + 三卡 + 联系 | 10 | 玻璃拟态、新粗野主义、拟物主义、儿童 / 亲子、温暖小店、企业科技蓝、SaaS 渐变、企业孟菲斯、北欧 Scandi、Web 2.0 玻璃 |
| `poster` | 巨字 + 单色横条 + 四格元信息 | 14 | 瑞士国际主义、Y2K 千禧、反设计、蒸汽波、奢侈品、瑞士海报、水墨、赛博霓虹、装饰艺术、丝网 / 孔版印刷、黑板粉笔、像素 / 8-bit、剪纸、复印小志 |
| `article` | 报头 + 窄栏正文 + 小标题 + 边注（报纸分两栏） | 11 | 杂志编辑风、裸 HTML、侘寂 × 北欧、单色极简、文档站、暗色编辑风、手账笔记、报纸、新中式、哥特暗黑、禅意极简 |

| `grid` | 满屏大小格（Bento） | 7 | Bento 网格、粘土拟态、Material You、Fluent 亚克力、极光渐变、数据看板、新拟物软 UI |

分配不是随机的，按风格在现实里的用途走：印刷流派给海报，工具类给控制台，杂志类给长文，网格体系给 Bento。**相邻两张卡尽量不同版式**（生成器按版式交错排序），形态变体（后台 / App）统一排在末尾，否则每一屏都是「同一风格的三张」。

## 一条做穿：Glass（深度）

40 多条落地页解决的是广度——一眼看出风格差异。但「首屏好看」不等于「能用」：真实项目里决定成败的是表格、表单、错误态、空态和弹窗。所以拿 `glass` 做了一条**参考实现**，位置在 `ref/glass/`，总览页是 `ref.html`。

**75 个 token，12 组。** 不再是 8 个色板值：底色层级（4 档不透明度 + 光斑 + 遮罩）、文字（4 级）、主色（含 `--accent-ink`，浅主色上必须放深字）、语义色（4 色 × 2 + `--on-danger`）、线（3 档 + 玻璃顶边高光）、玻璃与阴影（blur 三档 + 阴影三档）、圆角 6 级、字号 8 级 + 行高 3 档 + 字距 2 档、间距 8 级（4px 基数）、动效 3 档、层级 3 档。

**十屏，三套骨架**——同一套 tokens，但页面骨架完全不同，否则翻起来就是同一页重复：

- *应用壳*（侧栏 + 顶栏）：工作台（指标 + 表格 + 分页）、详情（事实栏 + 操作栏）、表单（成功 / 错误 / 只读 / 禁用 / 开关，错误态同时改边框、外环、文案、aria）、状态样张（按钮 7 态、输入 7 态、空态 / 错误 / 无权限三件套、骨架、toast、下拉、分页）、破坏性确认（遮罩只糊不换色）、浅色主题（同一份 HTML 只换 `data-theme`）
- *公开页*：营销页（透明导航 + 产品截面 + 三档定价 + 原生 `details` 做 FAQ）、登录（左证言右表单，左右分栏）
- *手机框*：390 宽做减法，整屏只两处 blur，列表行 58px 保证触摸目标
- *反例*：6 个做坏的玻璃，左错右对

**反例页是可判定规则的具体化**：纯色底上的玻璃、blur 46 + 边框 .6、三层玻璃叠加、浅主色配白字、全屏半透明没有锚点、渐变 + 强投影 + 亮边框三件套。每条都给了阈值和修法。

**校验脚本也覆盖它**：`tools/check.py` 会确认 `ref/glass/` 下三份 CSS 存在、页面只引用已定义的变量、不含外链与 `<script>`，并报出页数与 token 数。

```bash
python tools/check.py
# UI Atlas 校验 · 60 条风格 / 60 个样例文件 ＋ 参考实现 10 页 / 75 个 token
# 错误 0 条 ✓
```

**为什么只有一条**：它是模板，不是第 61 条风格。做完这一条才能估出「做穿一条」的真实成本（这份约 2,900 行），再决定是铺开还是只保留「反例 + 判定规则」这一层。

## 数据的体检

`python tools/check.py` 会检查：id 唯一、`styles.json` 与 `demos/` 一一对应、tokens 必填键齐全、样例不含外链与 `<script>`、`var(--x)` 必须已在 `:root` 定义、`features` ≥ 3 条。最后打一张表：每条风格的圆角、`ink/bg`、`ink/surface`、按钮色对比度、字号阶梯。

故意改坏一处，它会报出**文件与行号**。

## 内容与许可

所有样例都是本仓库自行实现的 CSS/HTML，**没有复制任何第三方站点的代码、截图或素材**。特征与提示词是对设计流派的方法总结；`sources` 只写流派与代表作品的名字，不引用具体站点实现。
