# UI Atlas · 网页 UI 风格与动效图鉴

**线上地址：<https://akikakoi.github.io/ui-atlas/>** —— GitHub Pages 托管，纯静态；[风格图鉴](https://akikakoi.github.io/ui-atlas/index.html)、[动效图鉴](https://akikakoi.github.io/ui-atlas/effects.html)、[动效系统](https://akikakoi.github.io/ui-atlas/motion.html) 都已上线。

60 个 UI 风格样例，铺在**五套版式**（落地页 / 海报 / 长文 / 控制台 / 网格）与**三种产品形态**（落地页 / 后台 / App）上。每条都是**零依赖的单文件 HTML**：打开就是完整页面，颜色、圆角、阴影、字体全部写成 CSS 变量。

另加一个 [动效图鉴](effects.html)：100 个可交互效果（指针 / 滚动 / 文字 / 布局 / 反馈 / 背景 / 转场）。和风格样例同一套约定——零依赖、单文件、尊重减动效——区别是这些页面要动手玩，并且能就地翻源码。

再往上还有一层 [动效系统](motion.html)：把 100 个片段收成 token、10 条编排规则、6 组反例，并用一个 [3 屏流程](motion/flow.html) 验证组合效果。

它不是截图集，是个能动手的工具：

- 改一个圆角滑杆，看 Bento 网格当场垮掉；
- 把改过的链接发人，对方看到同一套改动；
- 一键导出 Tailwind / shadcn 配置；
- 选两条风格，逐 token 看差异。

## 快速开始

```bash
# Windows：双击 启动预览.bat
python serve.py          # 默认 8760 起，自动挑空闲端口并打开浏览器
python serve.py 9000     # 指定起始端口
```

需要 Python 3.10+，无第三方依赖。**不要用 file:// 直接打开**：站点用 `fetch` 读 `styles.json`，浏览器会拦截。

## 两条轴：form 与 layout

风格的身份一半来自**编排**——瑞士是超大字和网格，终端是等宽行和提示符，杂志是栏宽和衬线，海报是一整张纸。颜色只是最后一层。所以除了「产品形态」，生成器还有一条「页面编排」轴：

**`form` · 产品形态**：6 个代表风格（glass / swiss / neubrutalism / ink / terminal / luxury）各补了后台与 App 两种形态。同一套 tokens 换一套骨架，验证的是**设计语言能不能撑住表格和列表**——很多风格在后台形态下会立刻露馅。

**`layout` · 页面编排**：48 个落地页不再共用「nav + hero + 三张卡」一个骨架：

| layout | 骨架 | 数量 | 谁在用 |
|---|---|---|---|
| `landing` | 导航 + Hero + 三卡 + 联系 | 10 | 玻璃拟态、新粗野主义、拟物主义、儿童、温暖小店、企业科技蓝、SaaS 渐变、企业孟菲斯、北欧 Scandi、Web 2.0 |
| `poster` | 巨字 + 单色横条 + 四格元信息 | 14 | 瑞士、Y2K、反设计、蒸汽波、奢侈品、水墨、赛博霓虹、装饰艺术、丝网印刷、黑板、像素、剪纸、复印小志、瑞士海报 |
| `article` | 报头 + 窄栏正文 + 小标题 + 边注 | 11 | 杂志编辑、裸 HTML、侘寂、单色极简、文档站、暗色编辑、手账、报纸、新中式、哥特、禅意 |
| `console` | 终端窗口 + 提示符 + 状态表 + 光标 | 6 | 终端、蓝图、全息 HUD、ASCII、琥珀终端、战术 HUD |
| `grid` | 满屏大小格（Bento） | 7 | Bento、粘土、Material、Fluent、极光、数据看板、新拟物 |

分配按风格在现实里的用途走：印刷流派给海报，工具类给控制台，杂志类给长文，网格体系给 Bento。画廊里**相邻两张卡尽量不同版式**（生成器按版式交错排序），形态变体统一排在末尾。顶栏有「版式」筛选，卡片上标出非默认版式；对比页遇到两条版式不同，会先声明「布局不能直接比，下面只比 tokens」。

原来的标题是设计评论（「一屏之内，说清所有事」），48 条读起来像同一个 SaaS 落地页。现在每条一个**它现实里会被用到的场景**：

## 图鉴能做什么

**改 token，实时看变化。** 详情页右侧的 tokens 是控件：颜色 → 取色器，`radius` → 0–40px 滑杆，字体栈 → 文本输入。改动通过 `iframe.contentDocument.documentElement.style.setProperty('--x', v)` 直接注入，**真的在改那个样例**。每个颜色 token 旁边标着 WCAG 对比度。

**详情是独立页面。** 点「看详情」跳到 `detail.html?id=<id>`：预览占满视口（海报、控制台、网格这类满版构图不再被裁），左栏 sticky 预览 + 右侧栏随滚动。画廊的筛选与滚动位置存进 sessionStorage，返回后原样恢复；直接刷新、新标签打开、把链接发人都成立。

**分享改过的版本。** 改动编码进链接（`detail.html?id=glass&r=0px&a=%23ff2d2d`），「复制分享链接」发出去，对方打开就是同一套改动，被改的 token 高亮。旧的 `#/s/<id>` 链接会自动重定向到新页面。

**导出。** CSS 变量 / `tailwind.config` 的 `theme.extend` / shadcn 的 CSS 变量（hex 自动转 HSL 三元组）。

**对比。** 选两条，顶部一句结论（「圆角 22px ↔ 8px；底色一暗一亮」），下面逐 token 列差异并高亮，两栏可同步滚动。

**搜索。** 同义词表 + token 特征词：`玻璃`/`glass`、`黑底`/`深色`、`圆角0`、`等宽` 都能命中；空结果时给三条相近的，而不是一句「没有」。收藏与最近浏览存 localStorage。

### 机制地图

100 条不再只按「指针 / 滚动 / 文字」分，而是先按底层机制归到 10 个族。卡片上的绿色标签是族名；如果某条只是同族的载体变体，源码弹层里会给出「同源」和跳转。

| 机制族 | 数量 | 判据 | 代表 |
|---|---|---|---|
| 指针距离场 | 11 | 光标到元素的距离决定位移、遮罩或缩放 | 磁吸按钮、Dock 邻近放大、文字探照灯 |
| 光标本体 | 2 | 替换或延展系统光标 | 自定义光标、光标拖尾 |
| 直接拖拽 | 8 | 按住物体，位移或进度跟手 | 拖拽惯性、旋钮拖拽、拖拽横滑 |
| 滚动进度 | 16 | 滚动位置映射成动画进度 | 视差分层、滚动缩放、滚动序列帧 |
| 字符序列 | 17 | 按字符或词拆分、排列与轮换 | 逐字上浮、字符抖动、数字里程表 |
| 布局重排 | 10 | 容器与元素重新落位 | 过滤网格、瀑布流、侧栏收轨 |
| 状态反馈 | 15 | 操作后的确认、失败与等待 | 堆叠提示、骨架屏、撤销删除 |
| 环境背景 | 10 | 不依赖操作的持续运动 | 粒子连线、字符雨、体积光 |
| 入场错峰 | 2 | 触发一次，元素按序错位出现 | 逐段入场、错峰入场 |
| 视图转场 | 9 | 页面或层级之间的切换 | 共享元素、页面推入、遮罩擦除 |

目前有 20 条被登记为同源变体，例如光标拖尾之于自定义光标、速度跑马灯之于双行跑马灯、文字探照灯之于光斑跟随卡片、滚动旋转之于滚动缩放、对勾描边之于长按确认。它们仍保留独立页面，但不再各讲一遍原理。

**准入规则**：新效果必须带来新的触发方式、时序结构或空间关系；如果只是换载体、换参数，登记为同族的 `variant_of`，不新增族。这样数量可以继续长，但机制不会重复膨胀。

几条共同约定：

- **优先只动 transform 与 opacity。** 入场、滚动、拖动都不碰 width / height，页面不重排；进度条也用 `scaleX`。少数效果必须动 `background-size`、`background-position`、`filter` 或 `clip-path`（荧光笔、渐变扫光、模糊聚焦、圆形擦除），代价写在各自的「注意」里。
- **预览可以等比放大，也可以打开真实页面。** 卡片右下角「放大」会按 600 × 450 的同一构图铺到全屏；「原页」（`view.html?id=<id>`）默认全宽打开效果所在的完整页面，页内可切「画板 600×450」对照构图。全部 100 条（旋钮拖拽 / 胶囊滑块 / 表格行展开 / 滚动缩放 / 磁吸按钮 / 光斑卡片 / 3D 倾斜卡片 / 自定义光标 / 列表悬停预览 / 点阵斥力 / 悬停放大镜 / 逐段入场 / 滚动钉住 / 错峰入场 / 按钮展开搜索框 / 页面推入 / 音频波形 / 对勾描边 / Dock 邻近放大 / 拖拽横滑 / 汉堡图标变形 / 延迟提示气泡 / 步骤条 / 底部导航 / 共享元素转场 / 遮罩擦除转场 / 拖拽底部抽屉 / 卡片展开 / 光标拖尾 / 拖拽惯性 / 拖拽擦洗 / 图片内平移 / 视差分层 / 滚动擦亮文字 / 阅读进度与章节 / 数字滚动 / 滚动速度倾斜 / 逐字上浮 / 乱码解码 / 打字机 / 双行跑马灯 / 文字翻转替换 / 光标裁切揭示 / 过滤网格 FLIP / 无缝手风琴 / 滑动下划线标签页 / 拖拽排序 / 收缩顶栏 / 可拖拽分栏 / 瀑布流重排 / 侧栏收轨 / 圆形主题切换 / 全屏菜单 / 顶部路由进度 / 3D 翻卡 / 荧光笔划线 / 模糊聚焦 / 渐变扫光 / 文字波浪 / 点击涟漪 / 堆叠提示 / 骨架屏到内容 / 点赞粒子 / 长按确认 / 按钮加载 / 表单错误抖动 / 自动保存状态 / 复制成功反馈 / 角标弹跳 / 下拉刷新 / 撤销删除 / 成功纸屑 / 数字里程表 / 字符抖动 / 弧线文字 / 下划线展开 / 描边填充文字 / 流动网格渐变 / 粒子连线 / 胶片颗粒 / 等高线波浪 / 星空穿越 / 流光边框 / 透视网格 / 字符雨 / 液态熔岩灯 / 体积光 / 卡片堆叠 / 滚动吸附 / 图文随行 / 滚动描边 / 滚动点亮文字 / 速度跑马灯 / 滚动序列帧 / 滚动旋转 / 滚动换色 / 关键词轮换 / 故障文字 / 文字斥力 / 文字探照灯）已重写成真实产品页面。
- **rAF 只在需要时跑。** 静止就停；canvas 在 `visibilitychange` 里暂停，别让几十个预览一起空转。
- **每个效果都给退路。** `prefers-reduced-motion` 下直接到终态；触屏没有 hover 就藏起指针效果；只有真按钮才做涟漪。
- **抢滚轮的效果标出来。** `pin`、`marquee` 这类在移动端要换原生横滑，卡片上标「慎用」。
- **难度分 1–3。** 基础 = 看懂就能写；进阶 = 有一个坑；复杂 = 要处理手势、性能或兼容。

**每条效果都有深度档案。** 点「代码」后，左侧除了做法与注意，还会给出：

- **解剖**：触发 → 过程 → 收尾，三段拆开；
- **参数**：时长、曲线、距离、错峰等实测值；
- **变体**：同一效果的两种低成本改法；
- **成本**：低 / 中 / 高与主要开销；
- **什么时候别用**：与「注意」分开，讲适用边界。

卡片上也会标出成本等级；手机上点弹层右上角的「深度」展开。

源码弹层给深度档案，也保留「关键点」三条判定标准与「用到的」技术标签；代码可按 全部 / CSS / JS 切换，一键复制。

### 加一个效果

1. 在 `effects/<id>.html` 写一个自包含页面：内联 `<style>` 与 `<script>`，底部留 `<p class="hint">` 写清怎么玩，并处理 `prefers-reduced-motion`。
2. 在 `effects.json` 里加一条：`id / name / name_en / cat / trigger / level / family / tech / features / how / watch / tags / demo`，再补 `depth`：`anatomy` ≥ 3 条、`params` ≥ 3 组、`variants` ≥ 2 条、`cost.tier` 取 `低 / 中 / 高`、`avoid` 一句话。若只是同族变体，再加 `variant_of: "<基准 id>"`。
3. 跑 `python tools/check_effects.py`。它查数据完整性、深度档案完整性、机制归档（`family` 合法、`variant_of` 必须同族且存在）、目录一一对应、无 `<link>` / 无外链 / 无 `<script src>`、有无 `.hint` 与减动效，并打印每条的行数与体积。

`trigger` 取 `hover / scroll / click / view / load / auto / drag`，`cat` 取七个类别之一；画廊的筛选、搜索同义词与「随机一个」都直接读这份数据。

## 动效系统：把 100 个片段收成一套语法

单条效果回答「这个动起来是什么感觉」，系统回答「什么时候该用哪一条、用多久、怎么组合」。

- **tokens**：5 个时长、4 条曲线、5 个距离、3 档错峰，共 17 个基础变量（另有一条 `--motion-primary` 组合）；`prefers-reduced-motion` 下统一压到 1ms / 0px，组件不写第二套逻辑。
- **10 条规则**：先决定要不要动、时长跟距离走、进入 / 退出曲线、一次一个主运动、错峰分组、保持空间关系、可打断、拖动跟手、减动效不是 0ms、性能预算。
- **6 组反例**：全屏模糊、滚动劫持、过度错峰、缺 reduced-motion、多个主运动、width 动画；每组给出错 / 对和修法。
- **3 屏流程**：[motion/flow.html](motion/flow.html) 把共享封面、骨架屏、错峰列表、装帧滑块、按钮 loading、toast、成功对勾串在一条时间线上；支持 View Transitions，不支持时退化为直接切换；有 busy 锁，导航可打断。
- **参数实验台**：[motion/lab.html](motion/lab.html) 拖动距离、时长、曲线、错峰、项数，实时跑 10 条规则体检；有推荐 / 太快 / 太慢 / 过度错峰 / 多运动 / width 六个预设，可复制 CSS 与分享链接。

入口是 [motion.html](motion.html)，token 在 `motion/tokens.css`。`python tools/check_motion.py` 会校验 token 齐全、三屏齐全、View Transitions 与减动效处理、规则 ≥ 10、反例 ≥ 6，以及实验台与组件工坊是否完整。

## 组件工坊：把高频效果带走

[components.html](motion/components.html) 不追求数量，只收 8 个最常用的效果：逐段入场、列表错峰、磁吸按钮、延迟提示、堆叠通知、骨架屏、无缝手风琴、复制反馈。

每个组件都有可以调的参数，而不是一段写死的示例：

- **显式参数**：位移、时长、曲线、错峰、半径、上限、停留时间等，滑杆和下拉实时生效。
- **实时预览**：面板里直接玩；「重播」不会刷新页面，只重跑当前组件。
- **三份代码**：JS 实现来自页面里同一份源码（`toString()` 导出），CSS 与 HTML 结构也一起给，一键复制。
- **退路完整**：`prefers-reduced-motion` 给终态；触发元素可聚焦；手风琴用 `aria-expanded`、通知用 `aria-live`、提示用 `aria-describedby`。
- **可销毁**：每个工厂返回 `{ destroy }`，重复初始化不会叠监听，也不会留下浮层。

用法就是「选组件 → 调参数 → 复制 JS / CSS / HTML」。组件本身零依赖，复制的代码可以直接放进现有页面。

## 性能与减动效审计

### 2026-11-11 静态审计（本地）

2026-11-11 对 100 条 demo、画廊挂载与组件工坊做了一次专项审计。

**挂载与内存**

- 首屏只挂 2 个预览：IntersectionObserver 进入视口前 500px 才设置 `src`，离屏不挂载。
- 新增「远处卸载」：离视口 1400px 以上把 iframe 切回 `about:blank`，同时最多保留 24 个；滚回来会自动重挂。
- 实测：滚到画廊底部只保留 1 个非空 iframe，JS 堆约 24 MB；修复前同路径会累积到 90–120 MB。回到顶部后前两张卡片能正常重挂，没有失败态。

**持续动画**

- 背景 canvas（粒子、点阵、波浪、星空、字符雨）都在 `visibilitychange` 时暂停；字符雨补上了这一条。
- 减动效下画布类改为静态一帧：点阵、粒子、波浪、星空、字符雨都还保留构图；纸屑不喷，光标拖尾隐藏。
- 悬停预览在 `prefers-reduced-motion` 下直接定位，不再做 0.16 的插值跟随。

**布局与滤镜**

- 仍有约 10 条用 width / height / max-height / padding 做局部过渡（tabs、segmented、sticky-header、morph-input、masonry、undo-delete 等）。它们都是小组件内部变化，代价写在各自的 `depth.cost` 里，没有发现整页重排。
- filter / backdrop-filter 集中在背景与玻璃类效果，预览被限制在 600×450 的 iframe 内，不会覆盖整页。
- `check_effects.py` 新增一条警告：背景 canvas 的 rAF 必须有 `visibilitychange` 暂停。

### 2026-11-12 线上实测

线上地址 <https://akikakoi.github.io/ui-atlas/>；Edge 157 通过 DevTools 协议跑，每个档位跑两次。桌面档 1440×900 / DPR 1 / 不降速（显示器 180 Hz，帧率上限因此是 180 而不是 60）；移动档 390×844 / DPR 3 / CPU 降 4 倍 / Slow 4G（下行 1.6 Mbps、RTT 150 ms）。每次都是全新标签、冷缓存。

**滚动**（5 秒内从 0 滚到 6000px，统计 rAF 间隔）

**CLS 的根因与修复**

首测时 index 与 effects 的 CLS 在 0.09–0.20，来源是页脚、筛选栏和收藏按钮。原因是同一件事：首帧网格为空、页脚落在视口里，JS 注入 100 张卡片后页脚被推走，同时滚动条出现又让整页横移 15px。修复是给空网格预留高度（`site.css` 的 `.grid:empty, .fx-grid:empty { min-height: calc(100vh - 150px); }`）。上线后四个档位复测 CLS 最大 0.0015，剩下一处是收藏按钮的亚像素位移。

**线上功能抽测**

- 100 张卡片全部渲染，计数「100 / 100 个」；首屏挂 9 个预览，其余按视口懒挂。
- 「放大」打开 magnetic.html?v=20261112，iframe 进入 ready；「看代码」拿到 14,758 字符源码。
- spotlight 的页内锚点从 0 滚到 765（到底），snap 从 0 滚到 916，自绘平滑滚动在线上生效。
- View Transition 可用，切换触发 1 次且内容更新；拖动排序把「夜航」从第 1 首移到第 3 首，live region 同步。
- 控制台唯一的 404 是演示页请求站点根 `/favicon.ico`：demo 是自包含单文件、不引外部资源，这是浏览器自己的探测请求。

**还没做**：物理手机（iOS Safari / Android Chrome）实测——移动档是 4× CPU + Slow 4G 仿真，不是真机；分钟级长滚动的内存曲线；Lighthouse 评分报告。仿真数据能定位瓶颈，但不能替代真机结论。

## 参考实现：把一条风格做穿

首屏好看不等于能用——真实项目里决定成败的是表格、表单、错误态、空态和弹窗。所以拿 `glass` 做了一条**参考实现**（[`ref.html`](ref.html)）：75 个 token、12 组；十个页面覆盖三种产品形态；一张反例页和 7 条可判定规则（blur 12–32px、边框亮度 .10–.24、一屏最多三层玻璃、必须有不在透明锚点……）。

- *应用壳*：工作台、详情、表单（错误态同时改边框 / 外环 / 文案 / aria）、状态样张（按钮 7 态、输入 7 态、空态 / 错误 / 无权限）、破坏性确认（遮罩只糊不换色）、浅色主题（只换 `data-theme`）
- *公开页*：营销页（定价 + 原生 `details` FAQ）、登录（左证言右表单）
- *手机框*：390 宽做减法，整屏只两处 blur
- *反例*：6 个做坏的玻璃，左错右对

它是模板，不是第 61 条风格——做完才能估出「做穿一条」的成本（约 2,900 行），再决定铺开还是只保留「反例 + 判定规则」。

## 数据的体检

```bash
python tools/gen_demos.py     # 生成 demos/ 与 styles.json
python tools/check.py         # 校验 60 条风格：0 错误才算过
python tools/check_effects.py # 校验 100 条动效：数据 / 自包含 / 减动效

```

`check.py` 检查：id 唯一、`styles.json` 与 `demos/` 一一对应、tokens 必填键齐全、样例不含外链与 `<script>`、`var(--x)` 必须已在 `:root` 定义、`features` ≥ 3 条、每条有 `sources` 与 `avoid`；参考实现的页面只能引用已定义的变量。最后打一张表：每条风格的圆角、三组 WCAG 对比度、字号阶梯。故意改坏一处，它会报出**文件与行号**。

`check_effects.py` 额外检查：`total` 与条目数一致、`cat / trigger / level / family` 取值合法、`variant_of` 指向同族已有条目、demo 文件名与 id 对齐、没有 `<link>` 与远程 `src/href`（内联 SVG 的 `xmlns` 除外）、有 `.hint` 与 `prefers-reduced-motion`、背景 canvas 的 rAF 有 `visibilitychange` 暂停，并列出每条的行数、体积与是否含 JS。深度档案也在这里兜底：`anatomy` ≥ 3、`params` ≥ 3、`variants` ≥ 2、`cost.tier` 合法、`avoid` 非空。

`check_motion.py` 检查动效系统：17 个基础 token 是否齐全、`tokens.css` 是否有减动效兜底、三屏是否齐全、是否使用 View Transitions 且有不支持时的退化、规则是否 ≥ 10 条、反例是否 ≥ 6 组；参数实验台要有 ≥ 5 个控件、≥ 10 条体检、≥ 4 个预设与复制入口；组件工坊要有 8 个组件、参数控件、复制入口与减动效处理。
