01

Token：先定尺子

点击任意一行可以复制变量引用。减动效时 tokens.css 会把时长压到 1ms、距离归零，组件不需要自己写第二套逻辑。

时长

距离越远，时长越长；不要所有效果都用同一个 300ms。

曲线

进入快出慢收，退出慢起快走；原地变化用 standard。

距离

位移只取五档；不要出现 13px、27px 这种无法解释的数。

错峰

同组元素依次进入；超过 8 项就分组，不要每项都延迟。

02

10 条编排规则

不是审美偏好，是可以在评审里直接判定的标准。每条都能在 3 屏流程 或 参数实验台 里找到对应实现。

01

先决定要不要动

只有状态变化才动：打开、完成、失败、切换。纯装饰的循环最多保留一个，否则页面一直在抢注意力。

02

时长跟距离走

4px / 120ms、8px / 200ms、16px / 320ms、26px / 480ms、整页 / 720ms。距离越远越慢，但不要超过 800ms。

03

进入 ease-out，退出 ease-in

进入要快出慢收，退出要慢起快走；原地变化用 standard。四条曲线够用，不要每个组件发明一条。

04

一次只允许一个主运动

同一时刻只让一个元素做主要位移或缩放，其余降级为 opacity。多个 transform 同时抢注意力，用户不知道该看哪。

05

错峰 40–110ms，超过 8 项分组

列表入场用 40–110ms 递进；10 项以上不要每项都延迟，分成 2–3 波，否则最后一项要等两秒。

06

保持空间关系

能共享元素就不要整页淡入：缩略图长成详情大图，用户知道「还是同一个东西」。没有空间关系时才用淡入。

07

可打断

新操作立即接管，旧动画不排队。用一个 busy 锁防止叠加；View Transition 未完成时不要再次导航。

08

拖动跟手

拖拽期间去掉 transition，直接把 dy 写进 transform；松手再做阈值判定。跟手的感觉来自「零延迟」，不是缓动。

09

减动效不是 0ms

直接给终态，保留状态反馈：加载完成、加入成功、页面切换都要有结果。不要只把时长改成 1ms 却留下位移。

10

性能预算

优先只动 transform / opacity；blur、canvas、大面积 clip-path 单独评估。4× CPU 降速下仍要能操作，不能掉到 20fps。

04

落进代码

组件只引用语义 token，不在自己的 CSS 里写 320ms 或 cubic-bezier。减动效由 token 统一兜底。

CSS · 主运动与错峰

/* 一条主运动 */
.card {
  transition:
    transform var(--dur-4) var(--ease-standard),
    opacity var(--dur-3) var(--ease-standard);
}

/* 列表错峰 */
.item {
  transition-delay:
    calc(var(--i) * var(--stagger-2));
}

JS · 先问系统，再决定播不播

const reduce = matchMedia(
  '(prefers-reduced-motion: reduce)'
).matches;

if (reduce) {
  el.classList.add('is-in'); // 直接终态
} else {
  el.animate(keyframes, {
    duration: 480,
    easing: 'cubic-bezier(.2,.8,.2,1)'
  });
}

View Transitions 也走同一套 token：::view-transition-group(product-cover) 用 var(--dur-5)，根转场用 var(--dur-4)。不支持的浏览器退化为直接切换，不阻塞主流程。

动效系统不是第 101 个效果，而是一层约束：token 决定尺子，规则决定取舍，流程负责验证。所有页面零依赖，可直接查看源码。
