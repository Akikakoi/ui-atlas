一条风格做穿：token 体系 + 10 个页面 + 反例

← 回到 60 条图鉴 打开工作台 ↗

60 条图鉴解决的是广度：一眼看出风格之间的差别。但图鉴里每一条都只有一个首屏， token 只有 8 个——它告诉你「长什么样」，没告诉你「怎么用」。 这一条是深度的模板：完整 token 体系（75 个变量）、十屏覆盖三种产品形态—— 后台（工作台 / 详情 / 表单 / 状态样张 / 弹窗 / 浅色 / 反例）、公开页（营销 / 登录）、移动端。 再加 7 条可以拿去吵架的判定规则。

十屏

三种骨架：应用壳 / 公开页 / 手机框。点开即看，零依赖、无脚本
01 工作台

侧栏 + 指标 + 表格 + 分页。四层玻璃，但只有两个不透明锚点——层级靠不透明度而不是阴影。

tokens.css · base.css · components.css
02 详情

左栏放事实（键值、订单、备注），右栏放操作（套餐、开关、危险区）。两栏都是同一档玻璃，靠空隙分组。

kv · timeline · switch · progress
03 表单

错误态同时改四处：边框、外环、文案、aria。顶部做汇总，免得用户在长表单里找不到出错那格。

field · is-error / is-ok · readonly / disabled
04 状态样张

按钮 7 态、输入 7 态、空态 / 错误 / 无权限三件套（别混用）、骨架、toast、下拉菜单、分页。

全组件 · 非理想态
05 弹窗

破坏性操作：遮罩只糊不换色（背景色斑还在），列清单说明后果，输入名称二次确认。

backdrop · modal · danger
06 浅色

同一份 HTML、同一份组件 CSS，只换 data-theme。塌了说明 token 没抽象干净，回去改 token。

[data-theme="light"]
07 反例

六个做坏的玻璃，左错右对，每一对只差一条规则。这页的颜色故意硬编码——反例不配用 token。

6 坑 + 7 条判定规则
08 营销页

没有侧栏：透明导航 + 大标题 + 产品截面 + 三档定价（推荐位）+ 原生 details 做 FAQ + 页脚。

mk-nav · mock · prices · faq
09 登录

左右分栏：左品牌区放证言，右玻璃表单。错误态与「显示密码」同框不打架。

auth-brand · auth-card · pw
10 移动端

390 宽真机框里做减法：整屏只有两处 blur，列表行 58px 保证手指够得着。

phone · m-balance · m-tab

Token 体系

75 个变量，12 组。页面里出现的任何颜色、间距、字号都必须来自这里
组变量数量为什么需要这一组
底色层级 --bg --bg-tint-1..3 --surface-1/2/3 --surface-solid --veil --overlay 10 玻璃的层次来自四档不透明度 + 背景光斑。只有一个 surface 的「玻璃」必然糊成一片灰。
文字 --ink --ink-2 --muted --muted-strong 4 浅色主题里 muted 必须比深色主题更深，否则在白色玻璃上直接消失。
主色 --accent --accent-ink --accent-weak --accent-line 4 --accent-ink 是关键：浅主色上必须放深字，硬塞白字是 2.4:1。
语义色 --ok / --warn / --danger / --info 各配 -weak，加 --on-danger 9 只用于状态，不用于装饰。徽章、提示条、危险按钮共用同一套。
线 --line-soft --line --line-strong --bevel 4 三档边界 + 一条玻璃顶边高光。随手写 rgba 是玻璃变脏的最常见原因。
玻璃与阴影 --blur-sm/md/lg --saturate --shadow-1/2/3 --glow-accent 8 blur 分三档（10 / 18 / 28），浮层比卡片高两档才浮得起来。
圆角 --radius-xs..xl --radius-pill 6 输入框小、卡片中、弹窗大。全站一个圆角值会让层级塌成平的。
字号 --text-xs..3xl（8 级）+ 行高 3 档 + 字距 2 档 13 这是图鉴里最缺的一组：8 个 token 拿不走排版尺度，而风格一半是排版。
间距 --space-1..8（4px 基数） 8 间距是节奏。设计稿与代码对不上，八成是间距没有阶梯。
字体 / 动效 / 层级 --font --font-mono；--dur-* --ease；--z-* 9 动效统一到 120 / 180 / 320ms 三档，避免每个组件各写一个 0.2s。

判定规则与坑

完整版在 07 反例页

七条可判定规则

  1. 背景至少一处低饱和彩色光斑，覆盖 ≥ 25% 面积；纯色底不做玻璃。
  2. blur 12–32px；低于 12 看不出材质，高于 32 边界消失。
  3. 面板边框亮度 rgba(255,255,255,.10–.24)。
  4. 一屏最多 3 层玻璃；第三层起用 --surface-solid 做锚点。
  5. 至少一个不透明锚点（主按钮 / 图表 / 头像），否则整页发飘。
  6. 文字对比度按面板叠底后算：正文 ≥ 4.5:1，18px 以上 ≥ 3:1。
  7. 阴影只用大扩散低透明度，不用方向明确的硬投影。

六个坑（都在 07 里）

  • 纯色底上放玻璃 → 变成一块更脏的灰。
  • blur 46 + 边框 .6 → 面板边界直接消失。
  • 三层玻璃叠加 → 越往里越脏，既不通透也不干净。
  • 浅主色配白字 → 2.4:1，按钮上的字看不清。
  • 全屏半透明、没有实心 → 表格里的金额最先被误读。
  • 渐变 + 强投影 + 亮边框三件套 → 一眼 AI 模板。

和图鉴的关系

这一条不是第 61 条风格，而是模板。它的价值不在「多一个玻璃拟态」，而在验证了一件事： 把一条风格做穿需要什么——12 组 token、7 个状态、1 张反例页。 如果这个成本可以接受，剩下 47 条就照这个骨架铺；如果太重，就只保留「反例 + 判定规则」这一层， 那是性价比最高的部分（每条新增成本约为页面的一半）。

反过来说，这十屏也暴露了图鉴现在的问题：原来的 60 条共用一套落地页骨架， 所以「识别特征」其实只是「首屏识别特征」。真实项目里决定成败的是表格、表单、错误态和弹窗—— 这些在这次之前一条都没有。

所有页面均为本站自行实现，无第三方代码或素材。tokens.css / base.css / components.css 可直接整套拿走。
